1. Start here

GET /api/v1/channels — everything else is a variation of this.

ParamWhat it does
page, limitPage number (from 1) and rows per page (default {{ page_size }}).
qSearch by channel name.
groupCategory, e.g. News. Comma-separate for several (News,Sports = OR).
serverStream host country (e.g. US). country alias. Comma-separate for several.
sorttrending (default), name, server, group, scanned / last_checked_at.
sort_dirasc or desc. Defaults to desc for trending / scanned.
statusonline (default), offline, unchecked, dead, or all. Combines with group / q / server (non-online may not load).
media_typelive (default) or vod.
include=facetsAdds category and server lists so you know valid group / server values.

Response shape

curl -sS "{{ base_url }}/api/v1/channels?group=News&sort=trending&limit=5"

{
  "ok": true,
  "page": 1, "per_page": 5, "total": 312, "total_pages": 63,
  "has_more": true,
  "next_url": "{{ base_url }}/api/v1/channels?group=News&limit=5&page=2",
  "wait_seconds": {{ wait_seconds }},
  "channels": [
    {
      "name": "Example News",
      "url": "https://example.com/live.m3u8",
      "proxy_url": "{{ base_url }}/proxy/stream?url=...",
      "logo": "{{ base_url }}/icons/example.png",
      "generic_logo": "{{ base_url }}/static/channel-generic.svg",
      "group": "News",
      "server": "US",
      "status": "online",
      "media_type": "live",
      "viewers": 3
    }

}

Play url directly, or proxy_url when you need same-origin / CORS-friendly HLS. Use logo for the channel-specific icon, or generic_logo when listing rows that have no art. Follow next_url until it is null, waiting wait_seconds between calls.

2. Grab specifics properly

Every filter is optional and they all AND together. Defaults are status=online and media_type=live — override status whenever you need offline / unchecked / all.

Offline + category + search (stacking)

This is supported today — pass status=offline with group and/or q (and server if you want). Responses include a warning that these may not load. 

# Offline channels in News whose name matches "BBC"
curl -sS "{{ base_url }}/api/v1/channels?status=offline&group=News&q=BBC&limit=20"

# Offline Sports on US hosts, newest scan first
curl -sS "{{ base_url }}/api/v1/channels?status=offline&group=Sports&server=US&sort=scanned&limit=24"

# Same idea as M3U
curl -sS "{{ base_url }}/api/v1/channels.m3u?status=offline&group=News&q=CNN&page=1" -o offline-news.m3u

# Unchecked (never scanned) in a category + search
curl -sS "{{ base_url }}/api/v1/channels?status=unchecked&group=Entertainment&q=TV&limit=20"
Discover valid categories & servers first

Facets live under .facets. Use those exact group / server strings in later calls.

curl -sS "{{ base_url }}/api/v1/channels?include=facets&limit=1" \
  | jq '{groups: .facets.groups[:8], servers: .facets.countries[:8]}'
By category
# Exact group-title match (use the string facets returned)
curl -sS "{{ base_url }}/api/v1/channels?group=News&sort=trending&limit=20"

# Page 2 of the same filter — prefer next_url from the previous response
curl -sS "{{ base_url }}/api/v1/channels?group=News&sort=trending&limit=20&page=2"
By server location (host country)
# ISO code — server= and country= are aliases
curl -sS "{{ base_url }}/api/v1/channels?server=US&sort=name&limit=25"
curl -sS "{{ base_url }}/api/v1/channels?country=GB&group=News&limit=10"
Search by name
curl -sS "{{ base_url }}/api/v1/channels?q=CNN&limit=10"
curl -sS --get "{{ base_url }}/api/v1/channels" --data-urlencode "q=Fox News" --data "limit=5"
Recently scanned (online vs offline)

sort=scanned (alias of last_checked_at) defaults to newest first. Stack with group / q / server.

# Just verified live
curl -sS "{{ base_url }}/api/v1/channels?status=online&sort=scanned&limit=24"

# Just marked offline
curl -sS "{{ base_url }}/api/v1/channels?status=offline&sort=scanned&limit=24"

# Offline + category + search + newest scan
curl -sS "{{ base_url }}/api/v1/channels?status=offline&group=News&q=CNN&sort=scanned&limit=20"

# Never checked yet (may not load)
curl -sS "{{ base_url }}/api/v1/channels?status=unchecked&limit=24"
On-demand / Videos
curl -sS "{{ base_url }}/api/v1/channels?media_type=vod&sort=name&limit=20"
# Offline VODs in a category
curl -sS "{{ base_url }}/api/v1/channels?status=offline&media_type=vod&group=Movies&limit=20"
More stacked examples
# US-hosted Sports that are currently online, trending
curl -sS "{{ base_url }}/api/v1/channels?server=US&group=Sports&status=online&sort=trending&limit=15"

# Names matching "BBC" on GB servers (online by default)
curl -sS "{{ base_url }}/api/v1/channels?q=BBC&server=GB&limit=10"

# Everything matching a search (online + offline + pending)
curl -sS "{{ base_url }}/api/v1/channels?status=all&q=News&limit=30"
Same filters as M3U (for VLC / scripts)
# One page of News as a playlist
curl -sS "{{ base_url }}/api/v1/channels.m3u?group=News&page=1&limit=50" -o news.m3u

# Full live lineup (no paging) for Jellyfin / Plex / Emby
curl -sS "{{ base_url }}/api/v1/playlist.m3u" -o live.m3u

# Full lineup with streams routed through this server's proxy
curl -sS "{{ base_url }}/api/v1/playlist.m3u?proxy=1" -o live-proxy.m3u
JavaScript: page until done
const base = "{{ base_url }}";
let url = `${base}/api/v1/channels?group=News&sort=trending&limit=50`;
const all = [];
while (url) {
  const r = await fetch(url);
  if (r.status === 429) {
    const wait = Number(r.headers.get("Retry-After") || 2);
    await new Promise((res) => setTimeout(res, wait * 1000));
    continue;
  }
  const data = await r.json();
  all.push(...(data.channels || []));
  url = data.next_url || null;
  if (url && data.wait_seconds) {
    await new Promise((res) => setTimeout(res, data.wait_seconds * 1000));
  }
}
jq one-liners
# Just names
curl -sS "{{ base_url }}/api/v1/channels?group=News&limit=10" | jq -r '.channels[].name'

# Name + playable URL
curl -sS "{{ base_url }}/api/v1/channels?server=US&limit=10" \
  | jq -r '.channels[] | "\(.name)\t\(.url)"'

# Prefer proxy_url for browser players
curl -sS "{{ base_url }}/api/v1/channels?q=CNN&limit=5" \
  | jq -r '.channels[] | "\(.name)\t\(.proxy_url)"'

3. Other ways to get the same data

Same catalog, different shape. Pick whichever your client handles best.

  • REST JSON
    {{ base_url }}/api/v1 Discovery index with every endpoint and its params.
  • File-style JSON (DB-backed, one URL per page)
    {{ base_url }}/streams.json {{ base_url }}/streams2.json  ·  /streams3.json … Easiest for loaders that can only fetch fixed URLs. Same rows as /api/v1/channels, plus a legacy streams key.
  • M3U
    {{ base_url }}/api/v1/channels.m3u?page=1 {{ base_url }}/streams.m3u  ·  /streams2.m3u … {{ base_url }}/api/v1/playlist.m3u Paged M3U for browsing; playlist.m3u is the full live lineup for media servers (add ?proxy=1 to route through this server).

CORS is open (Access-Control-Allow-Origin: *); methods GET, HEAD, OPTIONS.

5. Public, no key — with rate limits

  • No sign-up or key. Send a clear User-Agent.
  • Burst of about {{ burst }} requests, then roughly one every {{ wait_seconds }}s.
  • Too fast gets HTTP 429 with a Retry-After header — wait that long and retry.
  • Cache pages locally; don't poll in a tight loop. VRChat's own loader allows about one fetch per 5 s.

Full machine-readable spec: /openapi.yaml

6. Help keep the list fresh

Optional JSON POSTs. They share a separate, gentler rate limit.

POST /api/v1/watching — viewer heartbeat every ~20 s while playing. 
{"url": "<stream url>", "session_id": "optional-stable-id"}
→ {"ok": true, "viewers": 3}
POST /api/v1/report-playback — tell us a stream failed or loaded slowly so it's re-checked sooner. 
{"url": "<stream url>", "event": "no_playback"}            // or "slow_load"
{"url": "<stream url>", "event": "slow_load", "load_ms": 9400}
POST /api/v1/report-alive — an unchecked stream played for you: promote it and queue a priority check. 
{"url": "<stream url>"}
